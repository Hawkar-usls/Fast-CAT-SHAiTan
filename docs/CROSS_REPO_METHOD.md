# Cross-repository method reuse for PILOT_001

Fast-CAT-SHAiTan reuses **engineering patterns**, not scientific conclusions, from sibling JANUS repositories.

## Janus-Fundamentum

Role: epistemic and publication discipline.

Imported principles:

- every computational claim must point to committed code, fixed inputs and replayable evidence;
- a finite positive example is not promoted into a theorem or population-level biological claim;
- negative and inconclusive results are preserved;
- the independent verifier is a separate admissibility boundary;
- machine-readable status and claim ceilings are part of the experiment.

Effect on Fast-CAT: mostly **validity and auditability**, not raw landmark accuracy.

## Janus_Genesis

Role: deterministic provenance and fail-closed protocol machinery.

Imported principles:

- canonical JSON + SHA-256 manifests;
- replay of exact bytes/configuration;
- fail-closed evidence gates;
- append-only/anti-rollback thinking for admitted experiment records;
- preregistration against postselection;
- sequential/multiple-testing discipline when many clips/actions are inspected.

Effect on Fast-CAT: prevents a visually convincing result from silently changing source bytes, timing assumptions, thresholds, or the tested hypothesis after the outcome is known.

## janus-lapis

Role: candidate triage.

The useful Lapis idea is its `PASSED / REVIEW / REJECTED` gate and the principle that a high raw score is insufficient when the observation scene is noisy or not reviewable.

For Fast-CAT this becomes **clip eligibility**, with objective fields such as exact source/licence, raw-byte hashability, PTS/time-base availability, two-face visibility, stable cat identity, 48-landmark confidence, action visibility, occlusion/motion blur and independent frame review.

The numerical Lapis material/birth-gate constants are **not** imported. They were designed for a different sandbox and are not biological calibration.

## Janus-Demiurge

Role: legacy optimization toolbox.

Only the ordinary Bayesian-optimization pattern is reused conceptually:

```text
ask configuration
-> train/evaluate on frozen validation split
-> tell score
-> persist history
```

For a temporal model, candidate dimensions can include learning rate, embedding size, heads/layers, temporal-window length and event threshold.

The legacy `tachyonic`, digital-root and `filter_37` heuristics are explicitly excluded from Fast-CAT scientific optimization.

## CatGPT baseline

The pre-existing CatGPT model remains the interpretable baseline: context-conditioned transitions, n-grams, motion/time statistics, ear/head/body state and Slime Trace memory. It is not treated as a Transformer and it is not allowed to create timing truth. Source PTS remains authoritative.

## What these repositories cannot solve

None of these repositories can manufacture the missing visual measurement. The hard scientific bottleneck is still:

```text
raw frame
-> reliable two-cat face tracking
-> CatFLW-compatible 48 landmarks
-> validated CatFACS-compatible action onset
```

Fast-CAT therefore separates **measurement accuracy** from **evidence accuracy**. JANUS tooling can make the latter much stronger while a validated landmark/action detector is still required for the former.
